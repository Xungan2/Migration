# 平台缺口形态（platform-gap-pattern）

**签名**：设备/供给侧链路已证正常，但消费侧恒零——对照密度足够
（逐环节证明上游正常）后，断点落在目标 OS 平台层且属禁改文件。

**判别**：排除法实证链——逐环节证明上游正常（A 已证 → B 已证 →
C 路由正确）直到第一个恒零断点；断点即根因所在层。再核实该层
文件是否平台禁改（是 → 平台缺口；否 → 迁移代码问题）。

**归责**：platform

**建议动作**：`park` ——泊车 + platform_patches 登记（上游提案
素材）+ 判据 park。**勿继续烧轮次修不可修之物**；实证链本身
是产出（P7 素材）。

**实证**：INTX-DELIVERY（ICR=0x14 ∧ GSI=17 正确 ∧ irq_count≡0
→ ioapic 电平触发缺失；首现代价 ~1h，实证链成为上游提案）。
环境特定形态见 lineage 分区（如 rx-composite-signature）。
