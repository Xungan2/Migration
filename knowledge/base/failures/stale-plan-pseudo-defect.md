# 计划/文档过期型假缺陷（stale-plan-pseudo-defect）

**签名**：缺陷/失败的唯一依据是计划或遗留清单的**断言**（"文档
说缺 X 必须补"），而非任何脚本失败信号。

**判别**：**对照代码实测核文档**——grep 调用点拿 file:line，与
文档断言对照。代码已演进到位 → 假缺陷；真的缺 → 真缺陷。注意：
若不核代码直接"修复"，会给已正确的代码引入真 bug。

**归责**：criteria（文档错）

**建议动作**：`fix-criteria`（close_stale）——闭账 stale，
**必须附实测调用点 file:line 证据**（证明文档断言已过时）；
确认真缺则转 `fix-code`。

**实证**：RESET-HW-STALE（首现代价 ~20min；直接修复的返工风险
远高于核文档成本）。
