# knowledge/temp/ —— 知识草稿区（未审）

知识库三区模型（详见 `porter/bootstrap/kb.py` 模块文档）：

```
knowledge/
├── base/      # 工具随附的一般知识（任意目标 OS 可用；git 跟踪）
├── temp/      # 本目录：草稿区（骨架跟踪，内容全部 gitignore）
└── <name>/    # 一次迁移的知识库目录（p0 --kb 新建或指定；git 策略新建时定）
```

## 本区的定位

- 存放一切**未经人工审核**的知识草稿：固定域定点收成（maps 映射表、
  gaps 处置记录、runbook 手册、splits 策略样例）与随机知识候选；
- **agent 可写**（运行中自动产生），人随时可人工晋升
  （p1-promote / p2-promote / kb promote → 本次知识库目录）；
- 条目按 `<驱动名>@<目标OS名>` 或工作区命名空间隔离——本区跨迁移
  共享，多个工作区并行时互不覆盖；
- 未经审内容**不参与路由层自动应答**（信任分层：自动行为只依据
  人写的 policy 规则与人审过的知识）；相位 prompt 注入时带
  "未经人审"标注，与已沉淀冲突时以已沉淀为准。

## 目录结构（镜像知识库目录）

```
knowledge/temp/
├── maps/<驱动>@<目标>.md/.json      # P2/P3 映射表草稿（幂等覆盖）
├── splits/strategies/<驱动>.md     # P1 策略样例草稿
├── gaps/<api>.md                   # （后续切片）gap 处置草稿
├── runbook/                        # （后续切片）手册草稿
└── candidates/                     # （后续切片）随机知识候选暂存
```

## 约定

- 晋升后文件与索引条目搬入知识库目录对应位置，不双存；
- 长期滞留未晋升的草稿应清理或推动审阅，避免本区变成垃圾场。
