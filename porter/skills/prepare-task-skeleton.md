# 原生骨架实现、构建与载入验证

交付时同步维护工作区 `runner.md`：只整理目标系统迁移内部实际执行的模块编译、镜像编译、设备自启动、设备注入/交互和单元测试命令；成功和失败命令都记录，未涉及项留空。Porter CLI 调用记录在 `runbook.md`，不要混入 runner。无法从日志确认的迁移命令明确标注未知，不得臆造。

1. 按目标 OS 原生接口建立最小骨架、注册和初始化接线，先复用已知先例；保留必要错误处理。
   实现范围以给定 goals 为准，完整设备业务与完整单测不是默认交付要求。
2. 构建入口和环境明确后实际执行。保存工作目录、前置、命令、退出结果、日志及产物路径，
   用编译记录、依赖或产物证明骨架参与构建；无关构建成功不算本目标完成。
   构建使用带超时的前台命令直接取得退出码；后台启动验证按进程状态与证据检查，每次等待至多
   30 秒，证据齐备立即继续。日志保存到工作区 handoff 所在目录，完成一步即更新交接检查点。
3. 通过目标 OS 支持方式实际载入，保存本次输出并定位初始化或注册证据。源码中的打印语句、
   手写输出和 mock 不能替代实际载入。分别说明控制器、设备匹配、业务行为已验证到哪里。
4. 必要目标失败后只调查影响当前失败的信息；有失败证据与针对性修正才复验，在交接中记录
   每次命令、证据、修正及结果。没有新依据就交付 blocked，不用延长超时代替修正。
5. 构建与载入证据满足指定目标就交付。额外测试只执行已派发的补充验证目标，遵守其一次尝试
   限制。长命令设置超时，退出时清理本任务启动的进程和容器；交接保留可复现步骤。
