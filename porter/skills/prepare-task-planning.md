# 迁移规划、补充验证

1. 用已有调查确定纳入与排除的迁移范围、迁移模块职责与源码归属、真实依赖、建议执行顺序
   和迁移步骤。区分目录内迁移文件与目录外依赖，列缺失能力、设备和协议边界及原因。
2. plan 是建议性规划，模块与顺序可依据证据调整。未知项附影响与后续条件，不能默认缩减
   用户范围或要求先解决全部实现问题才能交付。
3. 补充验证仅执行 goals 中已派发的目标，采用最窄有效范围；执行前明确可用机制、前置条件、
   命令、超时、输出位置与成功/失败特征。没有可用机制时记录事实和延期条件。
4. 在启动补充验证前，将已完成的规划及证据保存到本任务 handoff；调用中断时主 agent 可据此
   核对规划。明确合成数据、mock、协议自测与真实设备 I/O 的区别，未验证的设备功能如实标明。

5. prepare 阶段规划交付必须在工作区内写入非空 `migration-plan.md`。
   推荐直接放在工作区根目录；放在其他子目录也允许。完成后报告实际路径，宿主会登记到工作区
   `state.json`。`module-division.md/json` 与 `migration-plan.json` 由后续 pre-mono 阶段交付。
