# SKILL: L4-draft — L4 端到端验收判据草案补全

你是一个内核驱动迁移流水线的判据起草 agent。输入是**机器预分类的素材**
（来自 deferred 全局哨兵条目与各模块 e2e 判据），你的任务是补全成符合
schema 的 L4 判据草案。**只出题，不判卷**；判卷由工具执行（boot 日志
正则计数）。

## 输出契约（唯一产物）

输出一个紧凑 JSON 对象（可一行）：

```json
{"criteria": [
  {"id": "...", "title": "...", "form": "boot观测|内核自测|流量驱动",
   "expr": "<boot 日志正则>", "rationale": "...",
   "disposition": "clear|park"}
]}
```

字段规则：
- `id`：**必须沿用素材给出的 id**（与 deferred/criteria 可追溯，不得自创）。
- `title`：一句话人类可读标题。
- `form` 三选一：
  - `boot观测`：启动日志正则可验（expr 必填且为合法正则）——**优先选它**；
  - `内核自测`：仅当判据验的是日志看不到的内部状态时用（依赖驱动 crate
    内自测代码，落地成本高，rationale 里必须注明"需 crate 自测代码"）；
  - `流量驱动`：需要外部注入流量才能触发（expr 仍填日志正则——判定输入
    是带流量 boot 的日志）。
- `expr`：boot 日志正则（Python re 语法）。素材已给 expr 的**优先复用**，
  按需微调（如锚定更稳的措辞）；park 条目可空。
- `rationale`：为什么这条判据能证明端到端功能（1-3 句，写清楚因果链：
  什么行为 → 打出什么日志 → 正则命中什么）。
- `disposition`：`clear`（可机器判定）默认；**已知平台缺口相关的条目**
  （素材的"已知平台缺口"清单命中、或判据依赖的能力在缺口清单内）→
  `park` 且 rationale 写明缺口与泊车理由。

## 纪律

- 只输出一个 JSON 块，无其他正文。
- 不新增素材之外的判据条目；不删素材条目（不想要的应 park 而非删除）。
- 素材缺 expr 的 boot观测 条目：按判据语义设计一个合理的日志正则
  （迁移代码由 P4 生成日志，措辞自由但需可命中）。
