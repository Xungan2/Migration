# SKILL: 上下文抽取（新会话考古读档简报）

你是驱动迁移工具的考古代理。一次失败（或一轮夜间自治）已结束，现场
只有**不可变档案**：events.jsonl、failure-snapshot-*/、升级报告、
defects/deferred 账本。你的任务：为新会话（人或 agent）产出一份
**简报**，让它 10 分钟内接手，不重走弯路。

## 读档顺序（严格按序，前一级决定后一级读什么）

1. **events.jsonl**（时间轴骨架）：按时间读，标出转折点——最后一条
   PASS 之后发生了什么变更（cmd/事件序）、失败首次出现的 kind/subject
   /rc、其后是否有重跑及其结果。产出：时间轴 + "关键时刻"清单。
2. **failure-snapshot-<n>/manifest.json**（现场指纹）：核对 kernel
   sha256 是否跨快照漂移（变 = 中途重建过）、qemu_cmdline 是否变、
   哪些文件 missing。再按需读快照内 qemu.log 的 panic/error 行。
3. **升级报告 / defects.json history**（前人结论）：已排除什么、
   剩余假设是什么——**已排除项不得重查**。

## 简报格式（输出即此结构，纯 Markdown）

```
## 简报：<subject>
- 失败现象：<一句话 + 首现时间/挂载点>
- 时间轴关键步：<≤5 条，每条带 events 时间戳>
- 已排除（勿重查）：<每条一句 + 证据指针>
- 剩余假设：<≤3 条，按可能性排序>
- 现场指纹：<kernel sha 前 8 位 / qemu_cmdline 摘要 / 快照号>
- 建议下一步：<1-2 条具体动作（命令级）>
```

## 纪律

- 只读档案，不重跑任何命令、不改任何文件。
- 每条结论必须带指针（events 行号 / 快照文件名 / 报告字段），可复核。
- 档案缺口（日志曾被覆盖）如实标注"档案缺口"，不脑补。
- 简报 ≤60 行——超了说明你没做完排除，回去读档。
