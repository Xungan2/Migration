# P0 骨架发现子任务

只完成任务数据指定的发现项，交付给下一个独立 session。读取前置
handoff 及其中的发现文件，核对前序先例对本项的适用范围后复用。
所有发现服务于零功能骨架：构建接线、真实匹配后的认领日志、最小单测。
不设计 I/O 转发、表加载、控制协议或其他驱动业务实现。
历史 raw.log 是失败诊断证据；仅在本任务失败摘要无法解释具体问题时定点
检索，不把整段旧会话当作发现输入。驱动身份以 Linux 输入源码及迁移意图
为准；目标接口与接线以当前目标树为准。

1. 从 Linux 注册入口与匹配条件确认认领对象，再查目标树对应接口。
   构建先例只证明构建接线；设备项须独立核对源驱动身份、目标总线或框架、
   注入对象与匹配路径是否对应。将 Linux 源码位置和匹配条件写入 findings。
2. 按给定字段记录确定的做法、必要签名或代码片段。证据只保留实际用到
   的源码位置，`quote` 为指定行的非空原文子串。
3. 字段齐全、接线证据可定位后立即写 JSON 并结束。尚未证实的行为记录
   到 `uncertainties`，留给后续真实验证；不要为消除所有疑问继续追实现。

设备项的 `injection` 指启动时如何注入源驱动对应的认领对象及参数入口，
`acceptance` 指该对象实际匹配后的认领日志（未匹配时不能出现）。缺少对应
接口或注入能力时，在相关字段及 handoff_summary 明确报告阻塞和所需能力，
保留已确认的构建发现；不得用另一类设备替代后宣称认领成功。
测试项只找骨架断言与原生测试接线，不设计驱动功能读写测试。

输出形态（字段列表由任务数据给出）：

```json
{
  "findings": {"指定字段": "结论、接口签名、接线方式或最小代码片段"},
  "evidence": [{"path": "相对目标树的路径", "line": 1, "quote": "该行原文子串"}],
  "uncertainties": [],
  "handoff_summary": "本项确认的事实、选择理由，以及交给下一任务的事项"
}
```

本项只读源码并写指定发现文件，不修改目标树，不生成完整施工单，不运行
构建、QEMU 或测试。只核对与本项直接相关的知识库条目，后续任务会负责
自己的发现和验证。将至少最后三分之一时间留给落盘；写完回复成果摘要。
