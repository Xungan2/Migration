## B. 逐知识详情（仅展开有修改的）

### B1 词典兜底回流（#1 扩展）
- **是什么**：翻译期兜底研究（交付物未裁定、翻译者查树自裁）发现的
  API 映射——**属类 1 词典知识，非错误处理**（2026-09-11 裁定）。
- **生成**：翻译者，翻译期；done JSON **可选**字段 `mappings`，
  schema 同研究者条目（symbol/verdict/usage/evidence[/notes]）。
- **落点**：机器收割进 mapping-notes.md，节 `## <模块> 翻译兜底`，
  行尾标注"兜底：翻译期发现"；幂等 = 节标题存在即跳过。
- **比对判据**：词典出现"翻译兜底"节且行格式合法；ledger 记录
  `dict_adhoc` 条数。

### B4 prunes 台账（#4）
- **是什么**：模块内"故意不迁"的显式申报（item/reason/源规格锚点）。
- **生成**：研究者，研究期，交付物 JSON 块（机器校验必填）。
- **消费**：翻译者（交付物全文注入，一次性，不变）+ **人（新增：
  终局审计"砍了什么"有总账）**。
- **形式**：`exp-mono/prunes.md`，每模块一节，行
  `- **item**：reason（锚 anchor）`，幂等 = 节标题判重（同三件套）。
- **A2（锚语法化 + 对账）不做**，挂 E 观察项。
- **比对判据**：每模块研究 PASS 后 prunes.md 有对应节；条目数 =
  交付物 prunes 数；report 有汇总。

### B5 negatives 收割与注入（#5）
- **是什么**："目标树没有 X"的排查结论（claim/evidence）。
- **生成**：研究者（skill 纪律一"负结论必须记"）。
- **形式**：`exp-mono/negatives.md`，**行级追加不分节**；claim
  规范化（去空白+小写）取 sha1[:12] 为签名；同签名 → 原行尾追加
  `<模块> 复证`（模块级幂等：模块名已在行内则跳过）——复现即更强
  证据，不丢弃。
- **消费**：翻译者（交付物全文，不变）+ **后继研究 prompt 注入**
  （「已排除死路」节，节头固定标注"历史结论，使用前须在当前树
  重新核实"）+ 人（report 计数）。
- **比对判据**：跨模块复证标注正确；`RES_*.prompt.md` 含该节；
  report 有计数。

### B7 open_questions（#7）
- **第 1 步（机器）**：`_run_research` PASS 时把 open_questions
  （question+verify）摘入 ledger research 条目；report 汇总——
  人首次可见"研究者在哪些点没把握"。
- **第 2 步（skill 路由）**：研究者——超出翻译者核实能力、需人工/
  产品裁定的问题**不放** open_questions，申报 parking
  （handling="等待人工裁定"、refill_when="manual"）；翻译者——
  遇超出裁定权的问题转泊车/notes 上报。三类去处定型：自查
  （open_questions）/ 人裁不阻塞（parking）/ 阻塞（blocked，已有）。
- **第 3 步（id 闭环核对）不做**，挂 E 观察项。
- **比对判据**：ledger 每 research 条目含 open_questions 数组；
  人裁类问题出现在 parking.md（路由生效）。

### B10 声明面 decl_fixed 留底（#10 小补）
- **是什么**：记账对不上被打回、重报后过——**当时对不上的是哪几条**
  留底（此前成功后只存重试计数，问题清单蒸发）。
- **形式**：ledger `entry["decl_fixed"]`（本 run 内历次打回问题
  清单的拼接）。
- **比对判据**：有重试且成功的模块条目中 decl_fixed 非空。

### B11 notes 研究侧对称化（#11）
- **现状**：翻译侧 done 也存（mono.py 已修）；研究侧仍只在 blocked
  时存——研究者 pass 路径的口头报告蒸发。
- **修改**：`_run_research` 对称化——parsed.notes 非空即存
  `entry["research"]["notes"]`（截 400）。
- **比对判据**：真跑 ledger 中 pass 的 research 条目可见 notes。

### B12 修复解法收成器（#12，最终范围）
- **收录范围（2026-09-11 裁定）**：**只收 run 内 gate 修复翻转**——
  rounds 里 static.ok=False（有签名）的轮 → 其后首个 ok=True 的轮。
  五类翻车场景的归宿：
  1. gate 修复（编译/启动/单测挂→修好）→ **fixes.md** ✅
  2. 记账修复（对不上→重报过）→ decl_fixed（B10）✅
  3. 兜底研究 → 词典回流（B1，类 1 知识）✅
  4. 格式修复（JSON 坏→重写）→ 不收（无领域知识）❌
  5. 跨 run 续跑翻转 → **不收**（续跑判定不在本轮 scope）❌
- **形式**：`exp-mono/fixes.md`，每模块一节，每翻转一条：
  轮 i→j｜签名｜修复段数｜失败日志指针｜**失败尾文内联（摘 12 行，
  防日志被 stem 复用覆盖——尾文必须自包含）**；幂等 = 节标题判重。
- **消费**：人（report 按签名聚类摘要）；未来 failures 域晋升候选
  （随 #14 推迟）。
- **比对判据**：rounds 里可见翻转的模块，fixes.md 有对应条目且
  尾文内联可读。

### F2. 偏差与新发现

1. **预算公式对现配模型偏紧**（工具旋钮层面，非协议违反）：默认
   研究 600s 在 defs/regs/scan 超时（3/7），翻译 900s 在 defs/caps
   超时（2/7）；全程人工 6 次续跑发起，其中 4 次带预算上调（研究
   1200/1500、翻译 1800/2400）。佐证 TODO §23 P1-2（模型感知预算）。
2. **fix_floor 盲区**：预算剩余 33s > 0 时过入口检查、段内被杀
   （defs run2 S2 33s 秒杀）——floor 只在 remaining ≤ 0 触发。修法：
   入口检查改"剩余 < 某阈值即视同耗尽"。
3. **跨 run 翻转按裁定不收**：defs/caps/spimem-io 的修复实际落在
   续跑 run 里（fixes.md 仅 4 起 run 内翻转）——若未来放宽裁定，
   需 ledger prev.status 翻转探测（实现草案曾在 B12 讨论中）。
4. **fixes.md 尾文是 gate 汇总行**（一层间接指向 build/ut 全文 log）——
   可接受的 v1 形态；改进项：沿"全文：〈路径〉"指针再抓一层。
5. **E 观察项取数**：E1 翻译者留锚——代码中实证裁剪注释锚（ids.rs:520、
   params.rs:196-209 等带源行号），偷渡审计留人审；E2 open_questions
   解答闭环未机器核（第 3 步缓做的代价，24 条存疑点在人审面）；
   E3 negatives 消费——复证引用实证且措辞含"亲测"（非盲抄）；E4 修复
   签名分布 4 起（单发为主，暂无重复签名）；E5 注入膨胀可忽略（33 行
   全量注入）；E6 兜底词典 3 行已入注入面，消费与否未逐一核。
