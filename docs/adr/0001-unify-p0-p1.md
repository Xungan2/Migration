# 合并 P0 与 P1 的执行流程，保留分别验收

P0 与 P1 共享源码调查、范围分析及源/目标 OS 知识沉淀，因此合并为主 agent 统一安排的执行流程，避免重复调查。保留骨架构建与载入、迁移规划两套验收职责；规划职责确定迁移范围、划分模块、整理依赖顺序，交付建议性 plan。消除固定的“副 agent”层级，由主 agent 按需派发子任务，子任务不继续委派。

两项验收分别记录，全部通过才算整体完成；续跑保留仍有效的证据，相关输入变化时复核。

子任务根据需要读取相关的先前任务 handoff，避免全量读取文档增加上下文。代码修改继续遵守单一写入者约束。

只有主 agent 执行验收，沿用已讨论的验收标准，无需重跑全部子任务。规划中的未知项直接记录到 AUTO-DECISION 和 AUTO-TODO。

后续执行可依据新证据调整模块划分与依赖顺序，并记入 AUTO-DECISION；改变用户要求的功能范围须由用户确认。

知识沉淀由一个专门的 agent 持续负责，以保证一致性。各任务只写自己的 handoff，知识 agent 统一写共享知识及 AUTO 文档；冲突先核对证据，无法消解则交主 agent 决定，验收权不转移。使用 opencode 续接机制维护知识会话，有新 handoff 或主 agent 决策时续接处理，无新输入时等待；整体完成前由主 agent 确认最后一批结果已经沉淀。

知识按主题目录组织，不要求源端、目标端集成、环境、构建、载入、测试和规划等主题各自维护一个大文件。目录内部的文件划分与结构由 agent 根据实际内容决定；共享知识仍由专门的知识 agent 统一写入。

仅维护本工作区知识，并注明适用版本与条件；跨驱动知识库不在本次范围内。主题目录按需创建，每个已创建的主题目录提供简短 README.md，描述内容并链接到具体材料；根 README.md 提供总入口。主 agent 按入口分配相关材料，子任务按需深入。

起始主题目录为 source/、integration/、environment/、build/、boot/、testing/ 和 plan/。verification.md、AUTO-DECISION.md、AUTO-TODO.md、AUTO-FIXME.md 保留为单文件，维护当前总览，详细材料链接到主题目录。verification.md 只记录主 agent 作出的验收结论。

知识 agent 可以自主移动、合并或拆分文档，更新当前索引，并在旧路径保留简短指向说明；历史 handoff 不改写，仍可沿原引用找到知识。

用户已结束设计讨论，并要求在 feat/unifyp01 分支只实现新架构、精简代码组织。新规划以 Markdown 交付，不以恢复旧 P1 机器产物和旧下游适配为本次目标。实施规格见 [统一 P0/P1](../specs/unify-p01.md)；决策已确认，不代表功能已经实现。
