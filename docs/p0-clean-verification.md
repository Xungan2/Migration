# 新 P0 的干净验证

目标是确认 Porter 能依据指定意图，在没有历史迁移成果的情况下建立并载入骨架。
使用独立源码副本和新工作区，保留用户现有工作。不要 reset、clean 或清空已有现场。

1. 选定未迁移的目标 OS 提交，创建独立 clone 或 worktree，记录提交号与初始
   `git status --short`。源驱动也记录版本；目标副本不含旧骨架和旧构建产物。
2. 准备指定意图，以及允许参考的环境资料。使用新容器或独立构建目录；资料写明
   本轮容器、挂载、可用工具与允许输入，排除其他工作区、知识、会话、日志和产物。
3. 使用从未执行过 P0 的输出目录，显式传入意图和允许的资料，省略 `--kb`。
   `--category` 可省略，以检查主 agent 能从自然语言与源码核实类型。
4. 执行完整 P0，保留 CLI 返回码、进程日志、当前知识和修改清单。检查类型、范围、
   骨架关系与约束是否有依据，完整迁移验收是否记录为后续项。
5. 查看本轮编译参与证据与实际载入证据，核对命令使用的源码、产物和运行环境。
   provider 替身、旧日志、静态打印语句或仅有成功标记都不能替代实际执行。
6. 如需验证意图续跑，再显式传入修订版本，检查受影响决策和证据得到复核。
   此次是同一验证现场的续跑，不再称为新的干净启动。
7. 停止本轮创建的 guest 和容器，保留日志及源码改动以供审阅。不要停止其他现场。

示例命令（路径替换为上述独立环境）：

```bash
python3 porter/main.py p0 \
  --linux-driver /path/to/source-driver \
  --target-os /path/to/clean-target \
  --output-dir /path/to/new-workspace \
  --intent-file /path/to/intent.md \
  --materials /path/to/allowed-environment.md \
  --budget 1200
```

完成条件仍按[P0 约定](p0-three-loops.md)。结果要分别说明自动化测试、真实执行
和独立复验的状态；当前仅执行 agent 自验。环境不足或预算耗尽时记录阻塞与
尚缺的证据，不能把已有知识或历史成功补写成本轮通过。
