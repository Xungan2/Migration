# SPI-NOR driver 的 Asterinas 迁移意图

将本仓库 Linux 5.10.265 的 `drivers/mtd/spi-nor/` 迁移为 Asterinas
原生安全 Rust 实现。目标 OS 默认采用本仓库的 `asterinas/`。

驱动类型：MTD（Memory Technology Device）类 SPI-NOR Flash 存储驱动。
可选类别提示为 `mtd`，由 Porter 核实与目标接入方向的对应关系。
使用场景是通过目标 OS 原生存储接口读写 Flash。以下功能与设备验证是
完整迁移目标；本轮 P0 按默认标准建立并实际载入骨架。

迁移主体包含 SPI-NOR 核心、JEDEC ID 识别、SFDP 参数解析、厂商设备表
及必要的设备修正逻辑。保留设备探测与初始化、读取、页编程、擦除、
写使能、忙状态轮询与超时、错误传播及退出时状态恢复的原有语义；
地址模式、协议选择和写保护按纳入设备的实际需求处理。

本次尚未指定目标 Flash 型号、SPI 控制器及验证板卡或模拟设备。
请在迁移策略中明确支持的设备与协议范围，列出所需控制器及目标 OS
依赖、无法支持的功能和原因，供人工审阅，不默认缩减为单一厂商或型号。
`controllers/` 中的驱动按实际硬件需要纳入，不要求迁移全部控制器。

以 Asterinas 原生设备与初始化机制接入。Linux MTD、SPI / SPI-mem
接口及公共头用于理解行为和依赖，不要求照搬整个 Linux 子系统；
缺失的必要能力须明确补齐方案。SPI-NAND、并行 NOR、Flash 文件系统
及 Linux 用户态 MTD ioctl 兼容不作为本次迁移主体。
驱动目录外的依赖须单独列出，不混入目录内迁移文件白名单。

验证应覆盖设备识别、擦除后读回、编程后读回、跨页读写、地址边界、
擦除对齐、超时与传输失败处理。使用目标 OS 支持的真实设备或明确支持
该控制器和 Flash 的模拟环境，在专用测试区域执行写入与擦除。
若尚无可用硬件或模拟环境，先验证协议与边界逻辑，并明确记录硬件验收
缺口；不能以 mock、空桩、始终成功返回或仅编译通过代替设备验证。
